# 저장과 음량 설정

기준: 2026-11-26 작업 트리 / v92. [현재 진행상황](PROJECT_STATUS.md)

## 저장소

게임 메뉴의 저장에서 자동저장과 수동 저장소 1~4를 표시합니다. 자동저장은 직접 덮어쓰지 않습니다.
수동 저장소가 비어 있으면 저장하고, 이미 파일이 있으면 덮어쓰기 확인을 받습니다.
시작 화면의 이어하기와 게임 메뉴의 불러오기에서 저장소를 선택해 복원합니다.
빈 슬롯이나 복구할 수 없는 슬롯은 불러올 수 없습니다. 백업 복구 가능한 슬롯에는 백업 표시가 붙습니다.
새 게임은 현재 버전의 자동저장을 갱신하며 수동 저장소는 유지합니다.

## 실제 파일 위치

Windows 배포본 기본값: `%LOCALAPPDATA%/TimeEscape/save/v<배포버전>`.
v92 배포 설정은 `jpackage.app-version=92.0`이므로 `save/v92.0`을 사용합니다.
버전이 같으면 압축을 다른 위치에 풀어도 같은 계정의 저장소를 사용합니다.
**새 버전은 별도 저장소로 시작하며, 이전 버전 파일을 삭제하거나 자동으로 가져오지 않습니다.**

| 저장소 | 본 파일 | 백업 |
|---|---|---|
| 자동저장 | progress.save | progress.save.bak |
| 수동 1~4 | slot1.save ~ slot4.save | 각 파일명 뒤 .bak |

`LOCALAPPDATA`가 없으면 사용자 홈의 `.timeescape/save`를 기준으로 합니다.
Eclipse 등에서 유효한 `jpackage.app-version`이 없으면 버전 하위 폴더 없이 기본 save 폴더를 사용합니다.
`-Dtimeescape.saveDir=<경로>`는 버전 분리보다 우선하는 개발용 저장 위치 지정입니다.
배포 ZIP에는 사용자 저장 파일을 포함하지 않습니다.

## 저장되는 진행

현재 schemaVersion은 2입니다. 방 ID, 완료 단계, 보유 아이템, 환경 플래그, 열린 방, 미확인 아이템 ID를 저장합니다.
연구 노트에서 마우스를 올려 확인한 아이템의 빨간 점은 저장 후 다시 나타나지 않습니다.
미완료 미니게임의 배치·배선과 연출의 순간 프레임은 저장하지 않습니다.
예전 schema 1 저장은 기존 복원 규칙으로 읽지만, 다른 버전 폴더를 자동 탐색한다는 뜻은 아닙니다.

파일 처리와 저장소 조회는 `SaveQueue`의 작업자에서 수행합니다.
완료·획득·사용·이동 등의 진행 변경은 자동저장으로 연결됩니다. 수동 슬롯은 직접 저장할 때만 갱신됩니다.
정상 종료는 저장 완료를 기다리며, 실패 시 창을 유지하고 안내합니다.

## 파일 보호

`SaveStore`는 UTF-8 데이터, SHA-256 손상 검사, 임시 파일 교체와 백업을 사용합니다.
백업에서 복구하면 이전 저장 시점으로 돌아갈 수 있습니다. 본 파일과 백업이 모두 손상되면 해당 슬롯을 불러올 수 없습니다.
SHA-256은 손상 확인용이며 암호화나 치트 방지 기능이 아닙니다.

## 음량은 진행 저장과 별도

`AudioSettings`는 배경음악·환경음·효과음 값을 `%LOCALAPPDATA%/TimeEscape/audio.properties`에 저장합니다.
버전 하위 폴더에 넣지 않으므로 배포 버전이 달라져도 음량은 유지됩니다.
환경 변수가 없으면 사용자 홈 `.timeescape/audio.properties`, 개발용 지정은 `-Dtimeescape.settingsDir=<폴더>`입니다.
슬라이더는 0~100이며 100은 현재 승인된 원래 믹스 크기를 의미합니다.
이 파일은 세이브 슬롯과 독립적이며 게임 패키지에 사용자 설정을 넣지 않습니다.

관련 코드: `SaveStore`, `SaveSlots`, `SaveQueue`, `GameState.restore`, `AudioSettings`, `GameMenuOverlay`, `GameFrame`.
