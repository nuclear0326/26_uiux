# v81 초기 실행 최적화 및 실제 검증

검증 날짜: 2026-11-25 (한국 시간)

## 실제 EXE 실행 비교

동일 기기와 런타임에서 v80, v81 순서로 번갈아 3회씩 실행했습니다. EXE 프로세스 실행 요청 직전부터 첫 JFrame의 WINDOW_OPENED 이벤트까지 동일한 Java 측정 에이전트로 측정했습니다.

|회차|v80|v81|
|---|---:|---:|
|1|1197 ms|757 ms|
|2|1076 ms|759 ms|
|3|1069 ms|765 ms|
|중앙값|1076 ms|759 ms|

중앙값 317 ms, 약 29.5% 단축. 최종 6회 모두 종료 코드 0, 오류 로그 없음.

전체 장면의 첫 프레임 렌더 완료나 모든 배경 준비 완료까지의 시간은 아닙니다. 탐색기 더블클릭 대신 EXE 프로세스 실행 요청을 사용했습니다. 재부팅/파일 캐시 초기화 없는 반복 실행이므로 보안 검사, 디스크 상태에 따라 달라집니다. 측정 도구의 초기화 비용은 두 버전 공통이며 배포본에는 도구를 포함하지 않았습니다.

예비 측정은 v80 1207/1150/1135 ms, v81 820/584/615 ms였습니다. 실행 순서 영향을 줄인 최종 교차 측정을 대표값으로 사용합니다.

## 적용 내용

1. 시계 균열 생성은 빌드 도구로 이동. 기존 좌표, 난수 시드와 출력 픽셀을 그대로 유지했습니다.
2. 소등 배경, 번개, 균열 레이어는 첫 창 표시 후 별도 작업으로 준비합니다. 이른 시작 클릭은 준비 완료 후 기존 소리와 연출을 시작하며 중복 입력과 화면 종료를 처리합니다.
3. 시작 화면의 이어하기/새 게임 확인 오버레이는 처음 필요할 때 생성합니다.
4. 비 데이터는 기존 압축 형식과 값을 유지하고 숫자별 읽기 대신 배열 단위 복사를 사용합니다. 압축 해제 중 약 7.68 MB 임시 바이트 데이터가 필요하지만 지속 보관하지 않습니다.
5. Windows 배포 폰트는 app/fonts의 원본 파일로 읽어 JAR 압축 해제와 임시 폰트 복사를 줄입니다. 별도 구성 요소 비교 중앙값은 스트림 199.1 ms, 파일 43.9 ms였습니다. 전체 실행 개선 시간에 합산할 수 없습니다.
6. 폰트 글리프와 디자인, 파일 바이트, 라이선스를 유지했습니다. 문자 축소나 손실 압축은 없습니다. 개발용 JAR는 폰트를 포함하고 Windows 배포 JAR만 외부화합니다.
7. 선택적 오디오 상세 진단 로그(timeescape.audioDiagnostics)를 추가했습니다. 사운드 데이터와 재생 로직은 변경하지 않았습니다.

- 비 효과 6개 시각(1시간 경과 포함) 픽셀 일치와 창문 3개 하단 적용 확인.

- 저장 복구 45개, 저장 큐 16개, 슬롯 20개, 비동기 슬롯 15개, 아이템 확인 상태 21개 통과.
- 단계별 치트 및 일반 완료 210개, 공통 퍼즐 실행 63개, 현재 퍼즐 모델 260121회 비교 통과.
- 비동기 오디오 26개, 오디오 디코더 18개 통과. 의도적으로 주입한 실패 테스트 메시지는 예상 결과입니다.
- Computer Use 실제 EXE 확인: 시작 화면, 시작 연출 후 연구실 진입, 메뉴, 수동 슬롯 1 저장, 메인 화면 복귀, 이어하기 표시, 슬롯 불러오기, 정상 종료.
- 실제 테스트 저장은 timeescape.saveDir로 별도 경로에 격리. 사용자 기존 저장 파일은 변경하지 않았습니다.
- 배포 JAR의 나머지 198개 항목 및 모든 외부 폰트/라이선스 원본 바이트 일치. ZIP CRC 정상, 측정 에이전트/저장 파일 미포함.

## 오디오 확인과 한계

첫 v81 실제 테스트에서 Audio unavailable / IllegalArgumentException이 발생했습니다. 동일 런타임 및 오디오 파일을 확인했고, 재검증에서 시작/천둥 클립 open=true, BGM/빗소리 open=true 및 running=true, 재생 위치 증가를 확인했습니다. 마지막 교차 실행 6회에서는 오류가 재현되지 않았습니다. 초기 장치 오류 원인은 확정하지 않았으며 음질을 사람이 청취한 검증은 아닙니다. 모든 환경에서 무오류나 동일 성능을 보장하는 결과는 아닙니다.
