# 현재 진행상황

확인일: 2026-11-28. 기준: 현재 작업 트리와 v118 배포 구성.
기획 목표와 실제 구현을 구분하며, 이 문서는 이번 코드 대조 결과입니다.

## v93 메모와 PC 변경

메모 클릭으로 CIPHER_TABLE을 획득하고 중앙 이미지로 열람합니다. 보관함에서 다시 볼 수 있으며 소유/미확인 상태를 기존 저장 형식으로 유지합니다. 비밀번호 입력은 PC로 이동했고 새 매핑에서 □ △ ☆ ○는 7135입니다. 해독표 보기 버튼은 입력 중인 값을 유지합니다.

v94는 USB 사고 로그 분석 PZ021과 수리 선행 조건을 구현했습니다. 6개 기록 순서 복원 후 정상/실패 로그에서 최초 이상을 찾습니다. 완료 보상 FAULT_REPORT와 미확인 상태를 저장하며 USB는 소비하지 않습니다. 필름/시계/책장 퍼즐은 아직 기획입니다.

## 현재 플레이 흐름

켜진 현재 연구실 → 시작 대사와 도움말 → 상자에서 장치 획득 → 보관함에서 사용 → 작동 실패·정전 → 배선 퍼즐로 전력 복구 → 해독표 획득 → PC 암호 입력 → Rush Hour → USB 복사 → 사고 로그 분석 → 장치 수리 → 과거 개방·이동 → 톱니바퀴 수리와 대체 부품 장착 → 미래 개방 → 임시 전력 합계 퍼즐 → 핵심 부품 장착·탈출 완료.

첫 사용에서 과거로 잘못 이동하던 흐름은 취소되었습니다. [현재 타임라인](OPENING_TIMELINE.md)을 기준으로 개발합니다.

## 후속 개발 및 정리 대상

- 미래의 `전원 켜기 (임시)`를 확정 기믹으로 교체.
- 추가 방·숨겨진 방, 열린 방의 양방향 재방문, 시대를 오가는 아이템 연계 확장.
- 총 20분 이상 플레이 목표에 맞춘 콘텐츠·난이도 검증. 현재 플레이타임을 달성했다고 확인한 상태는 아님.
- 로고 확정과 TIME ESCAPE 텍스트 교체.
- 개발용 Shift+8+9+0 스킵을 정식 배포 전에 비활성화하고 검증.
- 타임어택은 현재 구현 범위에서 제외.

위 항목은 후속 작업이며 이번 문서 정리에서 게임 기능을 추가하지 않았습니다.

새로운 수동 플레이, 물리 장치 음질 확인, 플레이타임 측정은 수행하지 않았습니다.

과거 기록은 [보관 문서](archive/README.md)에 있습니다.

## v96 화면 갱신 책임 분리

GameViewUpdater가 배경 시대, 전원, 상호작용 강조, 현재 목표, 위치 표시, 보관함 갱신을 담당합니다. GameFrame은 최신 GameState와 부품 선택 상태를 전달하고 기존 위치에서 자동저장을 요청합니다. Updater는 진행 상태를 보관하거나 변경하지 않으며 저장 요청을 하지 않습니다. 현재 목표는 전체 순서 대신 현재 단계의 행동을 표시합니다.

## v97 상호작용 분리

SceneInteractionHandler는 배경 클릭, 튜토리얼 상자, 메모와 아이템 수집 및 퍼즐 실행 조건 안내를 담당합니다. ItemUseHandler는 보관함 아이템 사용, 장치 이동과 수리 결과 안내를 담당합니다. InteractionHost는 현재 상태와 창/연출/오디오/저장 연결을 제공하며 GameFrame이 구현합니다. 퍼즐 최종 완료 콜백과 자동저장 위치는 유지합니다. 지연된 장치 콜백은 시작한 상태와 현재 상태가 다르거나 종료 중이면 무시합니다.

## v98 진행 세션 분리

GameSession이 현재 GameState, 게임 시작 여부, 새 게임 자동저장 초기화 예약, 저장소 목록 상태 및 SaveQueue를 소유합니다. GameFrame은 창과 UI 준비/전환만 처리하며 준비된 저장을 applyLoaded로 적용합니다. 저장 실패나 UI 준비 실패는 현재 진행을 교체하지 않습니다. 새 게임/다른 로드/종료 후 늦게 도착한 로드는 적용하지 않습니다. 저장 파일 형식과 슬롯, 기본 경로는 기존 SaveStore를 유지합니다.

## v99 컨트롤러 분리 완료

GameController가 GameSession/PuzzleRunner/두 상호작용 처리기를 연결하고 시작/완료/로드/종료 순서를 관리합니다. GameFrame은 GameView 구현으로 창과 UI를 구성하고 화면 요청을 표시합니다. GameViewUpdater, 퍼즐 규칙, 그림/음원과 저장 스키마는 유지합니다. [최종 흐름도와 전체 파일별 역할](PROGRESSION.md#v99-최종-흐름)을 참고하세요.


## v100 중복 요청 정리

장치 사용 콜백은 refresh를 통해 화면 갱신과 자동저장을 한 번 요청합니다. 엔딩 안내창 이전에 저장을 요청합니다. MissionPanel은 메시지 갱신을 EDT 큐에서 합치며, 전체 갱신이 먼저 처리되면 예약된 갱신은 취소합니다. 메시지만 바뀌는 경우에도 최신 문구가 표시됩니다.

검증: Java 167개 컴파일, headless 회귀 테스트 40/40 통과. 이전 배포 JAR와 비교한 변경 항목은 ItemUseHandler.class와 MissionPanel.class 두 개이며 이미지, 음원, 폰트, 런타임은 동일합니다. ZIP 무결성과 배포 폴더 일치를 확인했습니다. 게임 실행 및 실제 창 조작은 수행하지 않았습니다.


## v101 명세서 1차 수정

제작 부품은 사고 로그 분석 후 획득합니다. 이전 저장의 보유 아이템과 진행 중 수리는 유지합니다. Shift와 마우스 가운데 휠 버튼을 누르는 동안 같은 강조 효과를 사용할 수 있으며 도움말에 조작을 추가했습니다. 퍼즐별 문구는 승인 전까지 유지합니다. [전체 수정 계획](REVISION_PLAN_20261127.md)을 참고하세요.


## v102 PC 로그인 입력 개선

숫자 키패드와 원본 해독표 문양을 적용했습니다. 로그인 창 내부에서 해독표를 읽고 복귀할 수 있으며 입력값과 선택 범위를 유지합니다. 새 설명 문구는 승인 전이므로 게임에는 기존 문구를 유지합니다.


## v103 PC 문구 승인 및 Rush Hour 잘림 수정

PC 설명에 승인된 목표와 조작 문구를 적용했습니다. Rush Hour 콘텐츠는 RushHourPanel로 분리해 창 없이 렌더링과 조작을 검증합니다. 보드와 마우스 좌표에 같은 배율을 적용하며 조작 안내와 이동/초기화/힌트 버튼은 고정 영역으로 확보합니다. 긴 설명은 스크롤로 접근할 수 있고, 문구 축약은 승인 전까지 미적용입니다.


## v104 Rush Hour 지정 문구 삭제

보드 하단 영문 조작 문구, 상단 설명 문장, 이동 횟수, TRANSFER MANAGER, 선택 파일 이름과 안내를 제거했습니다. 하단 터미널 메시지와 닫기, 이동/초기화/힌트, 오른쪽 목표 및 조작 안내는 유지합니다. 게임 창 없이 관련 검증 3/3 통과, 두 창 크기에서 렌더링 확인 완료.


## v105 Rush Hour 디자인 확정

오른쪽 설명 카드는 크기를 유지하고 보드 영역과 세로 중심을 맞춥니다. 목표와 조작 안내 아래에는 초기화와 힌트만 배치합니다. 하단 터미널 설명과 피드백, 드래그 및 키보드 조작, 완료와 저장 경로는 유지합니다. 조원의 씨앗 심기 브랜치는 미병합입니다.


## v106 초반 미니게임 하단 통합
배선 복구(PZ004)와 PC 로그인(PZ006)은 공통 PuzzleWorkspace를 사용해 위쪽 퍼즐, 아래쪽 목표/조작 안내/버튼 구성으로 통일했습니다. 배선은 현재 단계 초기화와 단계 완료 버튼을 유지하며, 선택 시 선 지우기를 표시합니다. 되돌리기는 직전 칸으로 이동하는 방식이며 종료는 X/Esc로 통합했습니다. PC는 기존 키패드, Enter 로그인, 입력 유지형 해독표 열람을 유지합니다. 메모 이미지와 Rush Hour 디자인은 변경하지 않았습니다.

검증: Java 174개 컴파일, headless 회귀 테스트 44/44 통과. 배선 1000x820/900x760과 PC 900x680/820x620에서 실제 패널 렌더링 및 텍스트 경계를 확인했습니다. 배선 쉬움과 어려움의 마우스 풀이 및 단계별 완료 처리를 확인했고 게임 창은 실행하지 않았습니다.


## v107 배선 단자 조작
색 단자의 숫자와 하단 선 지우기를 제거했습니다. 왼쪽 색 점을 마우스 왼쪽 버튼으로 더블클릭하면 해당 선만 초기화하며 다른 색의 경로는 유지합니다. 선택 상태는 숫자 대신 색 이름으로 표시합니다. 기존 클릭 선택, 드래그/인접 칸 연결, 되돌리기와 단계 완료 규칙은 유지합니다.

검증: Java 174개 컴파일, 회귀 테스트 44/44 통과. 쉬움/어려움 및 두 지원 크기에서 왼쪽 단자 더블클릭의 해당 선 초기화, 다른 선 보존, 단일 클릭/오른쪽 단자/선 중간/오른쪽 마우스 버튼의 비초기화, 초기화 직후 이어 그리기와 완료 상태 갱신을 확인했습니다. 게임 창은 실행하지 않았습니다.


## v108 사고 로그 분석 드래그 정렬
사고 로그 분석은 기록 카드 전체를 드래그해 순서를 바꾸며, 삽입 위치를 파란 선으로 표시합니다. 범위 밖 드롭/포커스 상실/Esc는 드래그를 취소하고, 드래그 중이 아닐 때 Esc는 기존처럼 퍼즐을 닫습니다. 2단계는 행 전체를 클릭해 최초 이상을 선택합니다. 두 단계 모두 목표/조작/버튼을 하단에 배치하며 기존 기록과 정답, 저장 형식은 유지합니다.

검증: Java 175개 컴파일, headless 회귀 검증 45/45 통과. 두 지원 크기에서 모든 카드 이동 조합과 취소/종료 후 입력 차단을 검사했습니다. 실제 패널을 PuzzleRunner에 연결해 순서 복원만으로 보상/저장이 발생하지 않고, 로그 대조 완료 후 보고서/수리 개방/자동저장이 한 번 처리되는 것을 확인했습니다. 새로 불러온 자동저장에서도 상태를 유지합니다. 게임 창은 실행하지 않았습니다.
