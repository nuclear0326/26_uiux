# 새 시나리오 초반 이동

2026-11-25. 퍼즐 순서 관리표의 초반 현재에서 과거 오이동 구간만 구현했다.

## 플레이 흐름

1. 새 게임은 전원이 켜진 현재 연구실에서 시작한다. 전력 복구 퍼즐 완료를 위조하지 않는다.
2. 기존 배경 왼쪽 보관 상자(CASE 클릭 영역)를 조사한다.
3. TUT001 완료로 DEVICE를 한 번 획득한다. 획득 알림과 보관함의 미확인 표시를 재사용한다.
4. 연구 노트의 보관함에서 장치를 클릭한다. 상태 창을 닫으면 이동하지 않는다.
5. 사용 버튼을 누르면 ACT_FIRST_TRAVEL 완료와 device_broken 상태, past_1 개방을 기록하고 확정된 첫 시간이동 연출을 재생한다. 노트는 닫힌다. 연출 완료 시 과거로 이동하고 한 번 저장한다.
6. 갱신된 도착 위치와 장치 상태를 기존 비동기 자동저장 경로로 저장한다.

## 범위

- v83: 확정된 v6 시안의 소등, 깜빡임, 워프와 혼합 효과음을 적용했다. 전체 연출 종료 후 도착한 시대의 배경음으로 전환한다.
- 시작 메뉴의 기존 연출은 유지한다.
- 초기 현재에서는 기존 USB/장치 제작 미션을 실행하지 않고 상자 획득과 사용을 안내한다.
- 과거의 기존 톱니바퀴 퍼즐은 유지한다. 새 시나리오의 긴급 수리, 정전된 현재 복귀, 수평 미션은 다음 구현 범위다. 새 시나리오가 기존 수리 후 미래 직행 경로로 넘어가는 것은 차단한다.
- 배경 이미지와 소품 디자인은 수정하지 않았다. 보관 상자 위치는 기존 왼쪽 부품함을 재사용한다.

## 저장 호환 및 개발 규칙

- 새 게임 진입은 `GameState.newGame()`으로 통일한다. 초기화나 새 시작 경로를 추가할 때도 이 팩토리를 사용한다.
- 일반 생성자는 기존 진행 모델 및 저장 복원 기준을 유지한다. INTRO_START 완료 여부로 새 시나리오를 구분한다.
- 기존 저장은 새 시나리오로 강제 이전하지 않는다. 저장을 불러오면 이전 진행과 아이템을 그대로 유지한다. 새 흐름을 확인하려면 새 게임을 시작한다.
- 관리표의 첫 오이동 사건에 대응하는 코드 ID는 ACT_FIRST_TRAVEL이다. 기존 저장에서 사용하던 GATE001의 의미를 바꾸지 않기 위해 분리했다.
- INTRO_START, TUT001, ACT_FIRST_TRAVEL 및 device_broken은 기존 ID 집합 기반 저장 구조로 영속화하며 저장 파일 형식은 변경하지 않았다.
- 이후 현재 복귀를 구현할 때 intro_power_on 상태와 복귀 정전 상태의 우선순위를 확장하고 ACT_REPAIR/GATE002의 새 시나리오 제한을 교체해야 한다.
