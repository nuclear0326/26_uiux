# 대사 편집 안내

## 수정할 파일

개발 원본: `src/assets/dialogue/ko.txt`

UTF-8 텍스트이므로 메모장, VS Code 등에서 수정한다. 자바 파일에 문장을 추가할 필요가 없다.

```text
[intro.start]
시간이동장치의 시험 준비는 끝났다.
이제 직접 작동을 확인해 보자.
---
장치는 왼쪽 보관 상자에 넣어 두었다.
상자를 눌러 꺼내자.
```

- `[intro.start]`는 새 게임 첫 안내의 고정 장면 ID다. 이 이름은 유지한다.
- `---`는 다음 클릭에서 보여줄 페이지를 구분한다. 페이지 추가, 삭제, 순서 변경은 파일만 편집하면 된다.
- 일반 줄바꿈은 화면에도 반영한다. 한 페이지는 짧은 1~3줄로 작성한다.
- 빈 줄과 `#`으로 시작하는 주석은 표시하지 않는다. 빈 페이지나 중복 장면 ID는 허용하지 않는다.
- 대화창에는 인물 이름, 독백 제목, 테두리 없이 하단 그라데이션과 본문, 클릭 안내만 표시한다.
- 마우스 왼쪽 클릭 또는 Enter/Space를 놓을 때 한 페이지씩 진행한다. 표시 중 배경과 상단 버튼은 잠겨 잘못된 조작을 방지한다.
- 새 게임에서만 안내를 표시한다. 이어하기는 다시 표시하지 않으며, 대사 중 종료한 경우에도 저장된 게임 진행은 그대로 유지한다.

## 배포본에서 코드 재빌드 없이 편집

Windows 패키지 생성 시 `app/dialogue/ko.txt`를 JAR 밖에 함께 배치한다. 이 파일을 수정하고 게임을 다시 시작하면 적용된다. 실행 중 자동 새로고침은 하지 않는다.

파일이 없거나 형식이 잘못됐으면 JAR에 포함된 기본 대사로 대체한다. 개발 환경에서 원본 대사를 바꾸면 다음 실행부터 클래스패스의 리소스를 읽으며, 실제 배포에 포함하려면 다시 패키징한다.

## 이후 장면 추가

`[intro.pickup]`, `[intro.arrival]` 같은 새 구역으로 대사를 관리할 수 있다. 새 사건에 연결하는 코드는 처음 한 번 필요하지만 연결 후 문장 편집과 페이지 변경은 텍스트 파일에서 처리한다. 현재 연결된 사건은 `intro.start`뿐이다.

파일 읽기는 기존 백그라운드 리소스 준비 단계에서 수행한다. 본문은 Pretendard Regular, 계속 안내는 Pretendard SemiBold를 사용한다. 시네마형 대화창에 제목 글꼴은 사용하지 않는다.
# v86 타이핑 표시

대사 내용과 파일 형식은 그대로다. 한 페이지를 열면 140ms 뒤부터 38ms 간격으로 한 글자씩 표시한다. 대사가 출력 중일 때 클릭, Enter, Space는 해당 페이지 전체를 표시하며, 출력 완료 후 다시 입력하면 다음 페이지로 넘어간다. 현재 표시된 글자만 기준으로 줄바꿈과 높이를 계산한다. 첫 줄은 아래에 표시되며, 다음 줄의 첫 글자가 나타나면 앞줄이 위로 올라간다.

작은 키보드형 합성 입력음을 공백이 아닌 글자 세 개마다 한 번 재생한다. 오디오 클립은 재사용하고 오디오 작업 스레드에서 처리한다. 대사를 닫거나 전체 표시할 때 예약 입력음을 취소한다.

첫 시험 작동 전 Shift는 미획득 보관 상자만 강조한다. 획득 후 상자 강조는 해제되고, 사고 후부터 기존 진행도별 강조 규칙으로 돌아간다.
